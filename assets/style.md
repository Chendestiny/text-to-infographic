# 视觉规范（设计令牌）

**改风格改这里 + `scripts/theme.py`（皮肤令牌）/ `scripts/ink.py` / `scripts/decor.py` 里对应的常量。**
（本文只记录"值是多少、为什么是它"，工作流和版式字段见 [`../SKILL.md`](../SKILL.md) 与 [`../docs/`](../docs/)）

## 主题（皮肤）

**一套皮肤 = 一组设计令牌，不碰版式逻辑。** 本文下面写的所有值，都是**默认皮肤
`crayon`（蜡笔纸感）** 的取值；换 `meta.theme` 就是换掉这一整组。

规格里写一行就够：

```json
{"meta": { "theme": "crayon" }}
```

### 两个族（这是这一层最重要的概念）

皮肤分两类，**视觉语言根本不同**，不是"换个颜色"：

| 族 | key | 节点怎么画 | 重音怎么给 | 状态 |
|---|---|---|---|---|
| `paper` **纸张族** | `crayon` 蜡笔纸感 · `grid` 方格稿纸 · `retro` 复古报刊 | 手绘笔锋 + **上色方框**（蜡笔涂块） | 整块底色 | **已定稿** |
| `diagram` 工程族 | `terminal` 暗夜终端 · `blueprint` 工程蓝图 · `mono` 素白细线 · `nord` 北欧冷调 | **透明底 + 主题色细描边，无笔锋笔触** | 终端/蓝图：四角刻度；**素白/北欧：只有细线** | 版式仍在调整 |

**踩过的坑**：一开始只做了"换颜色"，把纸张族那套高饱和方框填色直接套到工程风上 ——
暗夜终端里一块块荧光填充块，跟"工程图"这个语义完全打架。
正解不是调色，而是**把"节点"这个原语本身做成族的职责**（`ink.node_box`）：
版式只管"这里有个节点、强调色是哪个"，由族决定怎么画。

### 工程族的节点口径（三条硬规矩）

1. **框的背景透明**，就是和底色一致 —— `node_surface` 留空 → `fill='none'`。
   ★ 不是"填一个比底色亮一点的面的色"：前者**网格会透进框里**，后者不会，
   在蓝图/终端那套坐标网格上差别一眼可见。
2. **边框是黑色或主题色** —— `node_line` 留空就用 `ink`（暗夜终端=荧光绿、
   工程蓝图=冷白、素白细线=黑、北欧=霜蓝）。别塞低饱和中间色，整页会灰蒙蒙没有图纸感。
3. **没有笔锋笔触** —— 画的是精确 `<rect>`，不走 `pen_rect` 那套"一条边拆 4 段收笔"。

那一处强调由 `node_style` 选形态：`corner` 四角刻度（**终端/蓝图用**：每角一对短线，
像取景框）/ `tab` 左上角实心块 / `rail` 左侧竖轨 / `rule` 顶边短线 /
`double` 内外双线框 / `none` 不画（**素白细线 / 北欧冷调用**：只有细线）。
比选：`python make_style_probe.py`（列 = 皮肤，行 = 方框方案 → 桌面 `t2i-box-styles/`）。

线宽 `node_w` 按皮肤各自定：终端 2.2 / 蓝图 2.0 / 素白 1.7 / **北欧 4.8**。
北欧的底色偏灰、对比低，2.4px 在它上面"飘"，实测要 4.8 才读得出框。

工程族另外统一的几处：`bullets` 的行也走同一套（透明底 + 主题色细边框 + 同一形态的角块，
由 `ink.node_mark_html` 保证和 SVG 侧一一对应）；金字塔的层轮廓用**统一的主题色**
（工程图里那是结构线，不是高亮，给每层配一个颜色反而像蛋糕）；
`hl` 高亮在深底上把透明度收到 `hl_alpha: 0.22`（0.30 会糊成橄榄色）。

### 挑皮肤

```bash
python make_theme_gallery.py --family paper    # 3 套 × 8 张样张 → 桌面 t2i-themes/
```

先看 `00-总览.png`，再看每套目录里的 `拼版.jpg`；README 里的皮肤图鉴由
`--sheet-out docs/images/themes/皮肤图鉴.png` 生成（行 = 皮肤，列 = 版式）。

**主题只换皮不换骨**：版式、字段、字数、四道门口径完全不变；`wobble: 0` 的皮肤
把整套手绘笔锋收成直线，`hl` 决定高亮是蜡笔色带、半透明色块、实心块还是粗下划线。

**加一套皮肤**：往 `scripts/theme.py` 的 `THEMES` 加一条字典，`ink.py` 一个字都不用动。
六条纪律写在 `theme.py` 的模块 docstring 里（先定族、颜色成套给、直线主题要收线宽、
深色主题别忘 `note` 色、工程族的调色板是强调色不是填充色、加完跑图鉴和测试）。

> ⚠ **文字色会跟着填充色自动反差**（`ink._ink_on`）：亮底写深字、暗底写浅字。
> 深色皮肤配高饱和填充时这是必须的 —— 实测终端主题的浅灰正文压在
> 琥珀/青/粉块上完全读不出来。判据是**填充色亮度**，不是"主题深不深"。
> 工程族的节点没有填充，所以这条对它不生效（文字就是正文色）。

## ★ 上色规则（和引擎行为一致）

1. **方框默认全部上色，颜色按页自动轮换** —— 作者不需要逐个指定 `fill`
2. 想让某个框留白表达"这一步不重要"，写 `"fill": "none"`（**不消耗轮换次序**）
3. 显式指定的颜色优先，也不消耗轮换次序
4. **框已上色时，框内文字不再画色带**（`plain=bool(fill)`）——否则色带和框色打架，
   黄框里画橙带看着像污渍。白底上的文字（compare 列标题等）保留色带
5. 色带宽度按**拉丁占比**轻微补偿（`1.0 + 0.08 × 拉丁占比`），不做整体放大——
   整体放大会把中文撑肥

## 字号

| 用途 | 值 | 常量 |
|---|---|---|
| 主标题 h1 | 88（weight 800，`line-height:1.14`） | `SIZES["h1"]` |
| 副标题 sub | 42 | `SIZES["sub"]` |
| 图内正文 | 52 | `SIZES["body"]` |
| 注释 | 38 | `SIZES["note"]` |

自适应规则（都是为了**不崩**，不是为了好看）：
- 主标题超宽**自动缩字号**（绝不折行）；有 `\n` 时按最长一行判断
- 副标题同理
- 备注/说明超宽**自动断行**（`txt_block`，最多指定行数，多了补省略号）
- 清单行高由**浏览器 flex 分配**，条数多时字号按比例缩小

## 宽度估算与校准闭环

`ink.tw(s, size)` = `Σ(CJK × size + 其他 × 0.62 × size) × CALIB`

- `0.62` 是拉丁字符的估算系数（字体度量估不准：拉丁偏宽、bold、letter-spacing 都是变量）
- `CALIB` 由 `pipeline.py` 的 measure 节点把**真实宽 ÷ 估算宽**回写，所以估算器越跑越准
- **不要手改 0.62 去"修"溢出**——那是反馈闭环的职责

## 描边与笔锋

| 项 | 值 |
|---|---|
| 手绘线 / 方框 | `SW_LINE = 6.0` |
| 箭头 | `SW_ARROW = 5.6` |
| 收笔 | 只占边的**末尾 12~18%**，3 段递减（宽 1.0→0.42，透明 1.0→0.60） |

两条硬约束：
1. **相邻段必须重叠**（`a -= 0.012`），否则渲染出来像线条断掉而不是收窄
2. **收笔不能太长**：早先 `t_start` 取 0.50~0.70，等于半条边都在渐变，
   在正常缩放下看起来就是"线断了"——这是实测踩过的坑

**主题缩放**：`hand_line` / `pen_edge` / `hrect_path` 的抖动与出锋都会乘上
皮肤的 `wobble` / `over`，线宽乘 `sw`。`wobble < 0.02` 时 `pen_edge` **直接
返回一条整边**（不再做收笔）——收笔是"手写感"的一部分，套在几何直线上
只是"线头莫名其妙变淡"，工程风皮肤看着像渲染坏了。

## 手绘原语

| 函数 | 职责 |
|---|---|
| `hrect_path()` | **单条闭合**手绘矩形——只有闭合路径能真正被 fill 填充 |
| `pen_rect()` / `pen_edge()` | 4 条带笔锋的边，只负责描边 |
| `pen_box()` | 填充 + 描边，并往方框清单注册（`measure` 要用） |
| `pen_poly()` / `_poly_fill()` | 闭合**多边形**（金字塔的梯形）的描边与填充 |
| `hl_line()` | 居中/左对齐文本 + 片段色带（会调 `maxw` 缩字号） |
| `txt_block()` | 自动断行的多行文本（备注用） |
| `hellipse()` | 两段不同半径圆弧拼成的开口椭圆 |

### 踩过的坑（别再犯）

1. **填充必须用闭合路径**：4 条独立开放折线拼框时，SVG 隐式闭合每条子路径，
   而"一条线"闭合面积 ≈ 0 → fill 等于没涂
2. **元素不许画到画布外**：`overflow:hidden` 会**静默**裁掉，不报错
3. **色带必须"先画完全部色带、再统一画文字"**：逐段交替输出时，后一段色带会盖住前一段的字
4. **不要手写 HTML/SVG 再让脚本"照着渲染"**：流水线只认规格，要特殊页用 `layout: raw`
5. **主题令牌不能用 Python 默认参数接**：`def pen_path(segs, color=INK)` 是 **def 期绑定**，
   换皮肤时它永远拿到首次导入时的那个值。要写成 `color=None` 再在函数体里回落到 `INK`。
   `decor.py` 的 `_shape(..., color=INK)` 踩过同一坑

## 字体

| 用途 | 字体 |
|---|---|
| 正文 / 标题 | 系统 CJK 无衬线栈：`PingFang SC → Microsoft YaHei → Noto Sans CJK SC → Source Han Sans SC → Hiragino Sans GB → Arial` |
| 备注小字 | **站酷快乐体**（随仓库分发，`assets/fonts/ZCOOLKuaiLe-Regular.ttf`，OFL 许可） |

皮肤可以覆盖字体栈（`theme.py` 的 `font`）：暗夜终端 / 工程蓝图用等宽栈
（`JetBrains Mono → Cascadia Mono → Consolas …` 后接同一套 CJK 回退，
这样拉丁是代码味、汉字仍然正常）。

- **只能随仓库分发 OFL 字体**。微软雅黑是微软商业字体，不能打包，
  所以它只出现在"系统字体栈"里当回退
- 早先用过霞鹜文楷（25MB），**已移除**：体积大，且在这台机器的 Chrome 里加载不了
- 字体完整性由 `doctor.py` 校验（读 TTF 表目录比对文件大小，下载被截断的坏字体会现形）

## 装饰零件库（`scripts/decor.py`）

固定一套，**不要每次让模型重新推**。按名字调用：

```python
from decor import decor, DECOR, DESC
svg += decor("gear2f1", 952, 112, 30)      # (x, y, size, seed, opacity)
```

| 名字 | 形状 | 归谁 |
|---|---|---|
| `gear1` | 单齿轮 · 空心 | 蜡笔纸感 / 方格稿纸 / 复古报刊 |
| `gear2` / `gear2f2` | 双齿轮 · 空心 / 都蜡笔灰填充 | 蜡笔纸感 |
| `star4` / `star5` / `star5f` | 四角星 / 五角星 / 蜡笔黄填充 | 蜡笔纸感 / 方格稿纸 / 复古报刊 |
| `cloud` | 云朵 · 蜡笔蓝填充 | 蜡笔纸感 |
| `plus3` | 三个加号 · 像素风（参考图左上角那串 `+++`） | 终端 / 蓝图 |
| `pixq` | 像素问号 · 方块拼 | 终端 |
| `crosshair` | 十字准星 · 圆 + 十字 | 终端 / 蓝图 / 北欧 |
| `corners` | **整卡**取景框角（四个卡角各一个 L 形，走 `card_corners()`） | 蓝图 |

**每套皮肤挑自己的零件组合**（`theme.py` 的 `decos`），空列表 = 这套皮肤不画装饰。

约定：
- 纯 SVG path/line，无位图无文字；统一跟随**当前皮肤的墨迹色**（`ink` 画装饰层前
  调 `decor.set_style()` 注入）；空心件透明度 0.42–0.55（不抢正文）
- 填充件 = 实色 62% + 白色斜纹（模拟蜡笔），不是死板纯色块；
  `wobble: 0` 的皮肤里抖动倍率归零，零件直接就是几何图形
- **半径上限 `ink.DECO_MAX_R = 40`**：内容区两侧各只有 `PAD_X`(=92)px 留白带，
  再大就会探进正文（实测终端主题的十字准星压到页脚注释上）
- 抖动幅度随 `size` 缩放；`clipPath` 的 id 用**全局计数器**生成，避免同页撞 id
- 签名统一 `(x, y, size, seed=1, opacity=None)`，x/y 是视觉中心；
  **一件零件整体占 2×size 见方**（摆位才好预算）

**布局规则**：每卡 3 个装饰（`corners` 除外，它是整卡件），落在 3 个**不同**槽位；
位置自动夹取（双齿轮向右伸约 1.9×size，不夹取会出画）；
**四宫格封面铺满画面，自动不加装饰**（否则齿轮压到格子边框）。

看零件长什么样：`python make_layout_gallery.py`（版式图鉴）——加了新零件或新版式都跑一次。

## 渲染后端

| 后端 | 用法 | 说明 |
|---|---|---|
| **CDP**（默认） | — | 纯标准库 WebSocket，不依赖 stdout，复用实例（~0.7s/张） |
| CLI | `T2I_BACKEND=cli` | `--headless=new --screenshot=`，兜底用 |

两条铁律：
1. **每次必须用全新 `--user-data-dir`**。profile 被别的 Chrome 占着时，
   新进程会把活交出去然后**静默退出**（exit 0、零输出）——这是最容易误判成"Chrome 坏了"的坑，
   详见 [`../docs/rendering.md`](../docs/rendering.md)
2. **Chromium 只认本机原生路径**：喂 POSIX 风格的 `/c/...` 会静默无产物，
   所以内部一律 `os.path.abspath()`

## 禁忌

- 不用纯黑 `#000`；不用渐变、投影、发光、模糊。
  **例外**（都由皮肤令牌控制，改皮肤时按这条核对）：
  `spectrum` 的箭头渐变（只允许 蓝 → 粉，两端不得出现灰或黑，
  且工程族会把它降级成一条细轴）；
  终端 / 蓝图 / 方格稿纸的**网格底纹**用的是 `linear-gradient` 画的 1px 网格线，
  不是花哨的颜色渐变
- 中文一律靠字体渲染，**禁止位图文字或 AI 生图出的字**
- 一页只讲一个点；箭头不许穿过文字
- 不把掘金 / CSDN 的跳转链接放进卡片
