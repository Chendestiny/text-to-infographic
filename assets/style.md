## 画布与留白

| 项 | 值 | 在代码里 |
|---|---|---|
| 输出 | 1080 × 1440（3:4），渲染 2 倍图 → 2160 × 2880 | `render.py` |
| 卡片 | 1008 × 1368，外边距 36 | `ink.W_CARD / H_CARD / MARGIN` |
| 卡片内边距 | 上 96 / 左右 92（**上下相同**，为 flex 布局留底） | `ink.PAD_TOP / PAD_X` |
| 内容可用宽 | **824** | `ink.W_INNER` |
| 方框内缩 | **8** | `ink.BOX_INSET` |

## ★ 上色规则（和引擎行为一致）

1. **方框默认全部上色，颜色按页自动轮换** —— 作者不需要逐个指定 `fill`
2. 想让某个框留白表达"这一步不重要"，写 `"fill": "none"`（**不消耗轮换次序**）
3. 显式指定的颜色优先，也不消耗轮换次序
4. **框已上色时，框内文字不再画色带**（`plain=bool(fill)`）——否则色带和框色打架，
   黄框里画橙带看着像污渍。白底上的文字（compare 列标题等）保留色带
5. 色带宽度按**拉丁占比**轻微补偿（`1.0 + 0.08 × 拉丁占比`），不做整体放大——
   整体放大会把中文撑肥

## 字号

| 用途 | 值 | 常量 |
|---|---|---|
| 主标题 h1 | 88（weight 800，`line-height:1.14`） | `SIZES["h1"]` |
| 副标题 sub | 42 | `SIZES["sub"]` |
| 图内正文 | 52 | `SIZES["body"]` |
| 注释 | 38 | `SIZES["note"]` |

自适应规则（都是为了**不崩**，不是为了好看）：
- 主标题超宽**自动缩字号**（绝不折行）；有 `\n` 时按最长一行判断
- 副标题同理
- 备注/说明超宽**自动断行**（`txt_block`，最多指定行数，多了补省略号）
- 清单行高由**浏览器 flex 分配**，条数多时字号按比例缩小

## 宽度估算与校准闭环

`ink.tw(s, size)` = `Σ(CJK × size + 其他 × 0.62 × size) × CALIB`

- `0.62` 是拉丁字符的估算系数（字体度量估不准：拉丁偏宽、bold、letter-spacing 都是变量）
- `CALIB` 由 `pipeline.py` 的 measure 节点把**真实宽 ÷ 估算宽**回写，所以估算器越跑越准
- **不要手改 0.62 去"修"溢出**——那是反馈闭环的职责

## 描边与笔锋

| 项 | 值 |
|---|---|
| 手绘线 / 方框 | `SW_LINE = 6.0` |
| 箭头 | `SW_ARROW = 5.6` |
| 收笔 | 只占边的**末尾 12~18%**，3 段递减（宽 1.0→0.42，透明 1.0→0.60） |

两条硬约束：
1. **相邻段必须重叠**（`a -= 0.012`），否则渲染出来像线条断掉而不是收窄
2. **收笔不能太长**：早先 `t_start` 取 0.50~0.70，等于半条边都在渐变，
   在正常缩放下看起来就是"线断了"——这是实测踩过的坑

## 手绘原语

| 函数 | 职责 |
|---|---|
| `hrect_path()` | **单条闭合**手绘矩形——只有闭合路径能真正被 fill 填充 |
| `pen_rect()` / `pen_edge()` | 4 条带笔锋的边，只负责描边 |
| `pen_box()` | 填充 + 描边，并往方框清单注册（`measure` 要用） |
| `pen_poly()` / `_poly_fill()` | 闭合**多边形**（金字塔的梯形）的描边与填充 |
| `hl_line()` | 居中/左对齐文本 + 片段色带（会调 `maxw` 缩字号） |
| `txt_block()` | 自动断行的多行文本（备注用） |
| `hellipse()` | 两段不同半径圆弧拼成的开口椭圆 |

### 踩过的坑（别再犯）

1. **填充必须用闭合路径**：4 条独立开放折线拼框时，SVG 隐式闭合每条子路径，
   而"一条线"闭合面积 ≈ 0 → fill 等于没涂
2. **元素不许画到画布外**：`overflow:hidden` 会**静默**裁掉，不报错
3. **色带必须"先画完全部色带、再统一画文字"**：逐段交替输出时，后一段色带会盖住前一段的字
4. **不要手写 HTML/SVG 再让脚本"照着渲染"**：流水线只认规格，要特殊页用 `layout: raw`

## 字体

| 用途 | 字体 |
|---|---|
| 正文 / 标题 | 系统 CJK 无衬线栈：`PingFang SC → Microsoft YaHei → Noto Sans CJK SC → Source Han Sans SC → Hiragino Sans GB → Arial` |
| 备注小字 | **站酷快乐体**（随仓库分发，`assets/fonts/ZCOOLKuaiLe-Regular.ttf`，OFL 许可） |

- **只能随仓库分发 OFL 字体**。微软雅黑是微软商业字体，不能打包，
  所以它只出现在"系统字体栈"里当回退
- 早先用过霞鹜文楷（25MB），**已移除**：体积大，且在这台机器的 Chrome 里加载不了
- 字体完整性由 `doctor.py` 校验（读 TTF 表目录比对文件大小，下载被截断的坏字体会现形）

## 装饰零件库（`scripts/decor.py`）

固定一套，**不要每次让模型重新推**。按名字调用：

```python
from decor import decor, DECOR, DESC
svg += decor("gear2f1", 952, 112, 30)      # (x, y, size, seed, opacity)
```

| 名字 | 形状 |
|---|---|
| `gear1` | 单齿轮 · 空心 |
| `gear2` | 双齿轮 · 空心 |
| `gear2f1` | 双齿轮 · 小的蜡笔灰填充 |
| `gear2f2` | 双齿轮 · 两个都蜡笔灰填充 |
| `star4` | 四角星 · 空心 |
| `star5` | 五角星 · 空心 |
| `star5f` | 五角星 · 蜡笔黄填充 |

约定：
- 纯 SVG path/line，无位图无文字；统一 `INK` 描边；空心件透明度 0.42–0.55（不抢正文）
- 填充件 = 实色 62% + 白色斜纹（模拟蜡笔），不是死板纯色块
- 抖动幅度随 `size` 缩放；`clipPath` 的 id 用**全局计数器**生成，避免同页撞 id
- 签名统一 `(x, y, size, seed=1, opacity=None)`

**布局规则**：每卡 3 个装饰，落在 3 个**不同**槽位；位置自动夹取（双齿轮向右伸约 1.9×size，
不夹取会出画）；**四宫格封面铺满画面，自动不加装饰**（否则齿轮压到格子边框）。

看零件长什么样：`python make_layout_gallery.py`（版式图鉴）——加了新零件或新版式都跑一次。

## 渲染后端

| 后端 | 用法 | 说明 |
|---|---|---|
| **CDP**（默认） | — | 纯标准库 WebSocket，不依赖 stdout，复用实例（~0.7s/张） |
| CLI | `T2I_BACKEND=cli` | `--headless=new --screenshot=`，兜底用 |

两条铁律：
1. **每次必须用全新 `--user-data-dir`**。profile 被别的 Chrome 占着时，
   新进程会把活交出去然后**静默退出**（exit 0、零输出）——这是最容易误判成"Chrome 坏了"的坑，
   详见 [`../docs/rendering.md`](../docs/rendering.md)
2. **Chromium 只认本机原生路径**：喂 POSIX 风格的 `/c/...` 会静默无产物，
   所以内部一律 `os.path.abspath()`

## 禁忌

- 不用纯黑 `#000`；不用渐变、投影、发光、模糊（**例外**：`spectrum` 的箭头渐变，
  且只允许 蓝 → 粉，两端不得出现灰或黑）
- 中文一律靠字体渲染，**禁止位图文字或 AI 生图出的字**
- 一页只讲一个点；箭头不许穿过文字
- 不把掘金 / CSDN 的跳转链接放进卡片
