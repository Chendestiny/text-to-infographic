# 排障手册

全部症状都来自实测。每条的格式是：**症状 → 原因 → 处置**。

先跑这一步，它能解决一半问题：

```bash
python scripts/doctor.py
```

它会逐项自检（Python / 依赖 / 字体完整性 / 浏览器 / **渲染后端预检**）并打印怎么补。

---

## 一、渲染类

### 截图全部失败、或返回 0 字节

- **原因**：CLI 后端的输出依赖 stdout / 文件落盘，受限沙箱会拦管道
  （报 `CreatePipe permission denied`）；或者 `--user-data-dir` 没生效导致
  Chrome 回落到**被用户浏览器占用的默认 profile**，新进程把活交出去后静默退出
  （exit code 0，零输出）
- **处置**：`T2I_BACKEND=cdp`（CDP 走 WebSocket，不受影响）。
  详见 [rendering.md](rendering.md)
- **别做的事**：不要下"Chrome 版本把 CLI 功能删了"这种结论——先实测

### 只有某一张图失败

- **原因**：那张的 HTML 有问题（不是后端问题）
- **处置**：`build/<spec 名>/card-XX.html` 用浏览器手动打开，看控制台

### 并发跑多个 pipeline 时随机失败

- **原因**：多进程抢同一个 profile 目录
- **处置**：顺序跑；或确认每个进程的 `tempfile.mkdtemp()` 目录互不重叠

## 二、溢出类（"溢出三兄弟"）

三道检查各管一段，报错信息里带 `kind` 字段：

| kind | 含义 | 谁管 |
|---|---|---|
| `out-of-canvas` | 文本超出 SVG 画布（会被静默裁掉） | 宽度类 → autofix 自动修 |
| `box-overflow` | 文本超出它所在的方框（画布内但压框） | 宽度类 → autofix 自动修 |
| `html-overflow` | HTML 行横向溢出 | 宽度类 → autofix 自动修 |
| `v-overflow` | HTML 行**纵向**撑破卡片底边 | 版式类 → **要改文案（减条数/拆页）** |

### 报 `needs_llm`：N 行 HTML 行撑破卡片

- **原因**：清单页条数太多（行高由浏览器分配，但字号会被压到很小）
- **处置**：按报错把该页**减条数或拆页**。契约里 `bullets.items` 上限 6 条

### 文字被裁掉一截，但没有任何报错

- **原因**：SVG 有 `overflow:hidden`，画到画布外的内容**静默消失**
- **处置**：跑 `measure.py` 或 `pipeline.py` 看 `out-of-canvas`；
  `raw` 页要自己算高度（见 [layouts.md](layouts.md) 的 raw 一节）

### 某一页的字突然比别页小

- **原因**：主标题/副标题超宽触发了自动缩字号（保证单行不折行）
- **处置**：把标题改短，或显式写 `\n` 控制断行（比自动缩字好看）

## 三、契约类

### `validate.py` 报一堆路径违规

- **原因**：文案超预算
- **处置**：按报错路径逐条改短；软约束（带「（软）」）可以先不管。
  详见 [contracts.md](contracts.md)

### 契约报错但看起来明明能放下

- **原因**：契约数值和引擎真实能力不一致（契约写小了）
- **处置**：造一张超限页实测——真溢出就维持硬约束，只是变密就改成 `soft: true`。
  **别直接放宽数值**

## 四、内容与语法类

### 高亮颜色不是我想的那个

- **原因**：不写颜色时按页**自动轮换**（蓝→黄→粉→绿→灰→橙）
- **处置**：想固定就显式写 `[[关键词|b]]`（显式色优先且不占用轮换次序）

### 色带看不见 / 和框色打架

- **原因**：那一行在**已上色的方框**里——引擎会自动抑制框内色带（避免色带和框色打架）
- **处置**：正常行为，不用处理

### `meta.frame: []` 报错

- **原因**：空数组会导致取模崩溃（已修，但仍建议不写空数组）
- **处置**：删掉 `frame` 字段即用默认 `["pen"]`；也可写 `["pen","card","none"]` 轮换

### YAML 规格报缩进错误

- **原因**：`{...}` 内联写法换行后缩进层级容易错
- **处置**：**改用 `.json` 规格**（零依赖、无缩进陷阱，也是推荐格式）

## 五、环境类

### Windows 上 `python` 找不到

- **处置**：用 `py -3`（官方启动器，`C:\WINDOWS\py.exe` 必然在 PATH 上）。
  实测最小 PATH 环境下可用（Python 3.11 + pyyaml 齐全）

### `pip install pyyaml` 失败 / 不想装

- **处置**：用 `.json` 规格，**完全不需要 pyyaml**（核心脚本只用标准库）

### 找不到浏览器

- **处置**：Windows 自带 Edge 通常能命中；否则
  `set T2I_BROWSER=C:\path\to\chrome.exe`（macOS/Linux 用 `export`）

### 字体没生效（回落到系统字体）

- **原因**：`assets/fonts/ZCOOLKuaiLe-Regular.ttf` 缺失或被截断
  （下载中断的字体文件看着有几十 MB 其实是坏的，Chrome 会**静默**回落）
- **处置**：`doctor.py` 带 TTF 完整性校验（比对表目录 `max(offset+length)` 与文件大小），
  报错就重新完整下载

## 五·五、读图能力：三态与"静默丢图"

判断模型能不能看图，**不能用"harness 有没有声明图片支持"作为依据**——必须真读一张
已知内容的图，并要求它说出具体内容。

| 状态 | 表现 | 危害 | 处置 |
|---|---|---|---|
| ✅ 能读 | 说得出具体内容 | — | 做审美终检 |
| ⚠️ **静默丢图** | 请求 200、回答流畅，但**没看到图** | **最危险**：Agent 会误以为已校验，检查报告里说谎 | 按不能读处理 |
| ❌ 纯文本 | 读图工具报错 | 低 | 老实跳过，如实说明 |

### 怎么判定

```bash
python scripts/vision_probe.py                 # 打印探针图路径（自带资产，不是现场生成）
python scripts/vision_probe.py --check "<模型回答>"
```

必须同时说出**红色**和**三角形**。只答"一张图""一张红色图片"→ 静默丢图。

> 探针图是**随仓库分发的固定资产** `assets/vision-probe.png`（512×512，约 2KB）：
> ① 内容恒定、可人工审阅（打开看一眼就知道该答什么，判定才公平）；
> ② 跨环境完全一致，不会因为现场生成而漂移；③ 离线可用，不往工作区写临时文件。
> 尺寸刻意做成 512×512 的合法大小：过大的图会先被服务端尺寸限制拦掉，
> 那属于另一类失败（不是能力问题），会干扰判定。

### 实测参考（本机 DSH + 阿里百炼通道，各环境可能不同）

| 模型 | 读图 | 依据 |
|---|---|---|
| qwen3.8-flash | ✅ | 答 "Red" |
| qwen3.8-max | ✅ | 答 "Red" |
| deepseek-v4.1-flash | ✅ | 答 "Red"，还认出"纯红方块" |
| kimi-k2.7-code | ✅ | 答 "Red." |
| glm-5.2 / glm-5.3 | ❌ 静默丢图 | 请求 200，模型说"没看到图" |
| MiniMax-M2.5 | ❌ 静默丢图 | 同上 |
| deepseek-v4-flash-0731 | ❌ 静默丢图 | 同上 |

**注意**：同一模型在不同 harness 下的结论可能不同——早期 `qwen3.8-flash` 曾在读图时
直接报 `model does not declare image input`，修好 harness 的能力声明后就能读了。
所以顺序是：**先查 harness 声明 → 再跑探针判实际能力**。

## 六、AI 行为类（写给 Agent）

### Agent 没跑 `validate.py` 就直接渲染了

- **原因**：没读 SKILL.md，或在凭印象干活
- **处置**：明确要求它按 SKILL.md 的五步流程走；`validate.py` 是**规格门**，不能跳

### Agent 手写了 HTML/SVG

- **原因**：它想"帮你修一下排版"
- **处置**：**明确禁止**。所有像素由脚本决定，一旦手写 HTML 就失去
  可复现 / 风格一致 / 可手改三件事。要特殊页用 `layout: raw` 并写进规格

### Agent 反复重试同一个失败命令

- **原因**：它没有拿到清晰的错误分类
- **处置**：让它先跑 `doctor.py` 看后端预检；把 `pipeline.py` 的完整输出贴出来，
  报错信息里带 `kind` 字段，可以直接定位
