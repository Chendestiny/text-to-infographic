# 字数契约

> **文字排版已改为 DOM**：折行 / 行数上限 / 垂直居中 / 字号自适应都由浏览器负责，引擎只给槽的矩形。本文中若出现 `wrap_text` / `fit` / `密集档` / `textLength` 等提法，属于**迁移前的历史机制**，现已删除或不再参与判定；详见 [architecture.md 的《文字排版：为什么是 DOM》](architecture.md)。

## 它解决什么问题

「版式能装多少字」以前只存在于代码行为里，于是每换一篇文章就出一次溢出：
文章 3 我边看边调能过，文章 1 就爆。**契约把容量从隐式行为变成可机械校验的声明。**

契约本体：[../templates/contracts.yaml](../templates/contracts.yaml)
校验器：[../scripts/validate.py](../scripts/validate.py)

## 数值从哪来

**不是拍脑袋，是实测上界**：取自方案图鉴（11 张渲染成功且好看的样张）里的真实文案，
再加上引擎的物理容量（比如 bullets 一行 200px、卡片可用高度约 950px）。

改契约时请遵守同一条：**用一张真的渲染过的样张定标**，别用感觉。

## 有效字数口径

```
汉字 = 1        其他字符（字母/数字/空格/符号）= 0.5
```

`[[关键词]]` 和 `[[关键词|b]]` 这类高亮标记**不计入**（渲染时才解析）。

例：`"① 注入 [[tools 定义]]"` → 去掉标记后 `① 注入 tools 定义` →
5 个汉字 + 6 个其他 = 5 + 3 = **8.0**，在 chain.steps 的 5–15 范围内 ✓

## 硬约束 vs 软约束

| 类型 | 标记 | 后果 | 处理 |
|---|---|---|---|
| **结构** | 条数 / 必填字段 | 条数越界、未知字段、页数超平台 | **必须改**，规格门报错 |
| **DOM 槽实测** | 浏览器量内容高 / 行盒 | 缩到下限仍放不下（`dom-overflow`） | **必须改**，像素门报错 |
| **建议值 M** | 契约里的 `max` | 只是「写起来好看的密度」，几何上可能仍放得下 | 提示，不阻断 |
| **写作建议** | 契约里的 `max` | 折行、行数上限、字号自适应都由浏览器负责 | 只是建议，改短更好看 |

为什么软约束的 `max` 比硬约束大得多（例：bullets `desc` max 34，而 chain `steps.text` max 15）：
前者是**两行的总容量**，后者是**单行**容量。

## 怎么读违规报告

```bash
python scripts/validate.py spec/<名字>.json
```

```
页数提示（1 处）：
  cards                          共 14 页 > 预算 9（推荐 4~9）；已经到 13 张以上，建议拆成系列

超过建议字数（浏览器仍放得下，能短更好看）2 处：
  card-05(chain).note            30.0 > max 24（软）  按书号找书一把好手，问…

契约违规（硬约束，必然溢出）3 处：
  card-03(chain).steps[1].text   17.5 > max 15   暴力检索 O(n)：全量必准，但扛不住量
```

**读法**：路径 `card-03(chain).steps[1].text` = 第 3 页（chain 版式）的 `steps[1].text` 字段。
按报错改那一条，重跑，直到硬违规为 0。

## 容量由几何决定（M 是建议值，几何是硬墙）

契约里的 `max`（本文后面统称 **M**）**不是墙**，它是"写起来好看的密度"。真实能不能放下由几何决定：
可用宽 ÷ 字号（还要看允许几行）。两者会同时出现两种错，所以现在分工明确了：

| 谁来判 | 判什么 | 结果 |
|---|---|---|
| 契约的 M | 密度是否好看 | **提示**："超过建议字数"，可改可不改 |
| 几何（`capacity.py`） | 图上放不放得下 | **硬墙**：`ok` / `dense`（小一号字，提示）/ `overflow`（必须改） |
| 结构检查 | 条数、未知字段、note 支持、页数 | **硬墙** |

严重度按**后果**分，但执行者已经换人了（DOM 文字）：

- **折行放不下** → 浏览器按 `-webkit-line-clamp` 裁剪 → `dom-overflow`（内容被藏起来）→ **硬**，改短文案
- **单行放不下** → 浏览器 autofit 缩字号直到塞进槽内 → 只有缩到 `min_size` 仍放不下才报 `dom-overflow`
- **末行只剩 1~2 字** → `dom-orphan` → **提示**（观感问题，能改就改）
- 契约里的 `max` 不再参与硬判定 —— 它只是写作建议（旧版把它当墙，实测会逼 LLM 做无意义的重写）

改文案之前先看它到底是哪一种：

```bash
python scripts/run.py spec/xxx.json --budget  # 逐槽：槽尺寸 + 起手字号
python scripts/validate.py spec/xxx.json     # 规格门：硬违规 + 各类提示
python scripts/pipeline.py spec/xxx.json -o out/   # 出图时还有"降级报告"逐卡点名
```

> 历史教训：arch 的 chip 契约写 ≤6，但 4 个 chip 时每格只有 179px、字号 44 →
> 真实只放得下约 3.7 个汉字。于是"规格门全绿 → 像素门连烧 3 轮 → calib 被抬到 1.39 伤及无关卡片"。
> 现在这种槽会被几何门当场拦下，一轮都不用烧。

## 页数契约（产品约束，不是字数）

字数契约管"这一条放不放得下"，页数契约管"这一篇该有几张"。参考值来自小红书配图规范：
**官方上限 1–18 张；**区间取 **4~9 张**（其中 6~9 是平台偏好区，短帖 4~5 张也正常）。
区间**只在 [../SKILL.md](../SKILL.md) 第 2 步定义一次**，这里和 validate.py 都引用它。
分档如下，只有最后一档才阻断：

| 张数 | 报什么 | 怎么改 |
|---|---|---|
| 4~9 | 通过（区间内） | — |
| > `meta.max_cards`（默认 9） | **页数提示**（软，不阻断） | 合并相邻小节：一页 `bullets` 放 4~6 条、`chain` 走 5~6 步 |
| ≥ 13 | 页数提示 + "建议拆成系列" | 拆成多篇，每篇 6~8 张 |
| > 18 | **硬违规**（退出码 1） | 平台发不出去，必须合并或拆系列 |

长文/教程类可以显式放宽预算（仍受 18 约束）：

```json
{ "meta": { "max_cards": 12 }, "cards": [ /* ... */ ] }
```

**页数由"切法"决定，不随文章行数增长**：张数 ≈ 1（封面）+ 章节数，再加两条修正——
平均每节 < 400 汉字时两节并一页、全篇 < 1.5k 汉字压到 4~5 张。
实测三例：8 节 / 2.6k 字 → 5 张；6 节 / 3.4k 字 → 7 张；6 节 / 0.9k 字 → 4 张。
按小节切（每个 `###` 一页）会切碎：一篇 228 行、5 章 9 个坑的文章按小节切出 11 张，
按章节合并只要 7 张。分规模对照表见 [../SKILL.md](../SKILL.md) 第 2 步。

> 渲染成本与页数无关紧要（1 页 ≈ 0.5 秒，100 页也就 50 秒），
> 卡页数是为了**读者划得完**和**Agent 少写少复核**。

## 契约的表达能力

```yaml
title: {min: 4, max: 14, lines: 2}      # 字数范围；lines 是提示（最多几行）
note:  {max: 44, soft: true}            # 软约束
steps:
  count: {min: 3, max: 6}               # 数组长度
  fields:
    text: {min: 5, max: 15}
ends:
  count: 2                              # 整数 = 恰好 N 个
  fields: {each: {max: 9}}              # 纯字符串数组用 each
```

## 契约和引擎必须对齐

契约写错了会**误报**（把能跑的规格拦下来）。改契约前先确认引擎的真实能力：

- `cover.items` 支持 6 个（>3 自动转竖排）→ 所以 `max: 6`
- `bullets.items` 行高由浏览器分配，理论上放得下更多，但**字号会小到不可读** → 所以 `max: 6`
- `timeline.steps` 纵向等距，最多 6 个不挤 → 所以 `max: 6`

**验契约的方法**：故意造一张超限的页，看引擎是真溢出还是只是变密。
真溢出 = 硬约束；只是变密 = 软约束。
